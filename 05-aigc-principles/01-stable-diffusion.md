# 01. Stable Diffusion 与扩散模型(文生图/图生图/inpainting)

## 1.1 业务定位与模块位置

**解决什么**: 把文本提示词/参考图/局部 mask 等条件,生成或编辑目标图像;用于文生图、图生图、局部编辑(inpainting)、证件照/头像生成与背景替换。

**输入**: prompt/negative prompt、seed、分辨率、steps、采样器(sampler)、CFG;可选:init image、mask、Control 条件图、LoRA 权重。

**输出**: 生成图像;任务日志(参数快照、耗时、错误码)用于追溯与复现。

**系统位置**: 推理服务核心 -> 入口校验 -> 入队 -> GPU 推理 -> 后处理(抠图/合成/裁剪) -> 存储/回传

## 1.2 核心理论:正向加噪与反向去噪(DDPM/LDM 直觉)

**训练**: 构造正向过程 q 逐步加高斯噪声;学习反向过程 p_θ 逐步去噪。

**Stable Diffusion 是 Latent Diffusion**: 在 VAE latent 上扩散,用更低维空间换速度与显存。

```
正向加噪:
  q(x_t|x_{t-1}) = N(√α_t · x_{t-1}, (1-α_t)I)
  x_t = √α̅_t · x_0 + √(1-α̅_t) · ε,    ε ~ N(0, I)
```

## 1.3 结构:VAE + Text Encoder + UNet(Cross-Attention)

- **VAE**: 像素 x -> latent z(压缩),z -> x(解码)。扩散在 z 上做。
- **Text Encoder**: 把 prompt 转成 token embedding。
- **UNet**: 多尺度去噪;Cross-Attention 把文本条件注入到图像特征里,决定语义对应到空间位置。

## 1.4 CFG:让模型更"听 prompt"

**Classifier-Free Guidance**: 同一步同时算 cond 与 uncond 的噪声预测,做线性组合放大条件方向。

```
ε = (1+w)·ε_cond - w·ε_uncond
```

w 越大,生成的图像越贴合 prompt,但多样性下降。

## 1.5 sampler/steps/seed:可控性与复现

- **steps**: 迭代次数,影响细节与耗时。
- **sampler**: 数值更新策略,影响稳定性与质感。
- **seed**: 固定随机性;配合参数快照实现复现。

## 1.6 img2img 与 inpainting:条件与约束差异

- **img2img**: 从输入图 latent 加部分噪声再去噪;strength 决定保留结构程度。
- **inpainting**: mask 限定修改区域;mask 边缘要羽化避免黑边。

## 1.7 高频追问点

### Q: 性能口径怎么报?

**端到端** vs **纯推理**;同时报分辨率/steps/sampler/并发/硬件。

### Q: 如何防雪崩?

限制参数、队列限流、错误码、可恢复错误重试。

### Q: 简历里写的耗时 4.5s → 1.6-2.0s 怎么来的?

**口径**: 同一硬件、同一分辨率、同一 steps/sampler/CFG;区分端到端耗时还是纯推理耗时。

**优化手段**: FP16(降显存 + 加速)、batch(提升吞吐)、预加载(避免重复 load)、多进程/多实例(提高吞吐)、限流(避免并发把 GPU 打满)。

### Q: 稳定性和失败率怎么降?

**"分层处理"**:
1. 入口校验:不合规参数直接拒绝,避免进入推理
2. 超时:推理与外部依赖都有超时
3. 重试:只对可恢复错误重试(网络/资源抖动);参数错误不重试
4. 可解释错误码:错误码 + 人都能看懂的提示

这是**有边界的重试**,不是无限重试把系统拖死。

## 1.8 高频追问: 怎么保证证件照风格一致?

不是靠 prompt 让模型"自己学一致",而是靠模板化:
- 分割 + 加图锁定主体边界
- 背景模板锁定颜色与质感
- 裁剪规则锁定比例
- 参数锁定降低随机性
- 必要时 LoRA 固定风格、ControlNet 固定结构

## 1.9 评估指标体系

**不能用单一分数定胜负**:
- **线上质量**: 人工抽检 + 失败类型统计(跑偏、空图、构图错位等)
- **离线对比**: 固定输入与参数组 A/B,关键场景做对比集
